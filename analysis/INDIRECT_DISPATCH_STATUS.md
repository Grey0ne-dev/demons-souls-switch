# Verified indirect callsites and typed dispatch

The pinned lift omitted LR updates for indirect linked branches. Old Switch
checkpoints restored those return PCs in individual audited adapters. The local
lifter now emits LR=instruction-address+4 for bctrl/blrl and their conditional
linked forms, preserving the old LR target before overwriting it for blrl.
Unlinked and untaken branches preserve LR. Nine compiled execution tests pass
(`python3 switch-port/tests/test_lifter_links.py`). Existing translated chunks
were not regenerated by that source fix.

The Switch slice generator has an explicit --annotate-indirect-calls option.
It checks the exact ELF SHA-256, original body hashes and the original function
range export SHA-256 f8396569c426921d1d9e586fa5ff60096b9cbdfefcd8d330f971eeb7d03d7e42.
For each selected body containing indirect call statements, it scans the original
executable instructions in the exported range for unconditional bctrl words
(0x4E800421). Statement/instruction counts must match exactly; an ambiguous
mapping is refused. Ordered markers carry the original return PCs. Current
selection: 177 pinned bodies, 58 annotated sites in 25 functions.

Annotated bodies differ only in their indirect-call marker statements; provenance
explicitly sets function_bodies_unmodified_from_pinned_local_lift=false and lists
all original return PCs. Normal unannotated generation remains available for
the legacy checkpoint tests. Source body hashes always refer to the original
pinned local lift, including the documented unsupported bootstrap patch.

The exploratory dispatcher checks the original bctrl opcode, executable target,
main TOC and a backed matching OPD, then calls only a known selected native
function through a generated typed switch. It restores the actual LR and drains
typed trampolines. Unknown functions, unannotated sites, unsupported services,
foreign TOCs and wrong opcodes stop explicitly. It does not provide arbitrary
native pointers, fake return values or general scheduling.

Validation compares the automatically dispatched first two constructors with
the manually audited path: identical function order, stop ABI and every byte of
both ELF segments except the actual per-run clock timestamp. A deliberately
wrong return PC is rejected before a constructor executes. The automatic path
records 3,610 checked accesses versus 3,686 on the legacy path because legacy
adapter validation uses traced reads; the original instruction memory effects
are identical. These counts must not be presented as a performance measurement.

The first three constructors return in 213 entries / 4,141 checked accesses.
The next descriptor is 0x0195FFE0 / code 0x009E54C8. A production validator checks
the third object's parent, the two name records, eight sorted opaque key/object
pairs, the earlier node/vector and unchanged pool allocation/service totals.
An explicit development constructor limit remains separate from a validated
checkpoint. No result establishes complete game boot, rendering or gameplay.
